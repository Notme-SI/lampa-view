# Проверка производительности ТВ в 0.4.62

Сравнение 0.4.61 (`b17e597`) и 0.4.62: Chromium, экран 1920 × 1080, режим ТВ, замедление CPU в четыре раза, каталог из 60 карточек. Для каждого варианта выполнены два прогона. Сеть и изображения подменены локальными тестовыми ответами; скорость реального TMDB, Lampac и физического телевизора не измерялась.

| Сценарий | 0.4.61 | 0.4.62 |
| --- | ---: | ---: |
| Вызовы `getBoundingClientRect` при подготовке каталога | 523 | 423 |
| Измерения после серии переходов посторонней кнопки | 160 | 0 |
| Измерения после серии событий фокуса карточек | 160 | 88 |
| Записи постоянного кеша после повторного фокуса | 1 | 0 |
| Запросы изображений главного баннера и соседей за сценарий | 4 | 2 |
| Запросы исходных изображений `/original/` | 1 | 0 |

Сценарий не измеряет FPS и не позволяет обещать определённую скорость на телевизоре. Он показывает, что плагин выполняет меньше лишних обходов и запросов в одинаковых условиях. Размер баннера на ТВ ограничен `w1280`; на компьютере прежний выбор размера сохранён.

Для повторения нужны Playwright и установленный Chromium. `PLAYWRIGHT_MODULE` может указывать на внешний модуль Playwright, `PLAYWRIGHT_BROWSERS_PATH` — на каталог браузеров.

```sh
git show b17e597:dist/lampa.js > /tmp/lampa-0.4.61.js
node tools/profile-tv.cjs /tmp/lampa-0.4.61.js dist/lampa.js
```

Проверки регрессий используют настоящий клиент Lampa с тестовыми сетевыми ответами:

```sh
node --test tests/tv-artwork-priority.test.cjs tests/tv-performance.test.cjs
```

Отдельно проверяются зависшая первая обложка, ограничение числа параллельных загрузок, ожидание остановки пульта, невидимые карточки, устаревшие ответы, загрузка баннера перед логотипом, повторное использование следующего слайда и сохранение изменившегося рейтинга без повторных записей неизменившихся данных.
