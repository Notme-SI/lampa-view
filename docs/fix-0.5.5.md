# 0.5.5 — Повторная выборка верхнего цвета Safari

Проверка пользователя на iPhone после 0.5.4: системная строка остаётся зелёной при переходе на синий фон «Люпена». 0.5.4 нельзя считать подтверждённым исправлением на физическом iPhone.

Причина по коду WebKit: LocalFrameView::fixedContainerEdges использует старый цвет того же контейнера, если не найден явный backgroundColor. Полноэкранные слои также предпочитают предыдущий оттенок. Нужен реальный закреплённый край с непрозрачным background-color, высотой больше thinBorderWidth=10, а не только метатег или CSS-градиент.

Источник: https://github.com/WebKit/WebKit/blob/main/Source/WebCore/page/LocalFrameView.cpp

- Добавить край 12px только для iOS/«Стекла». Без участия в потоке, без событий, доступен только как декоративный слой. Цвет из существующей кешированной палитры; плеер — чёрный.
- Сохранить viewport, status-bar-style=default, высоту и координаты навигации. Удалять край при смене темы/отключении. На остальных платформах оставить прежнее число фоновых слоёв.
- Тесты восстановления, нативных цветов, обе темы в Chromium/WebKit, актуальные CI и Pages. Скриншоты не делать. Саму системную строку эмулятор не проверяет.

Проверено перед публикацией: сборка ES5, 361/361 тест, Chromium/WebKit desktop/TV/mobile. Реальный край покрывает ширину окна, имеет явный цвет и высоту больше порога WebKit, не участвует в потоке, не перехватывает ввод; координаты нижней навигации и viewport неизменны. Проверка самого цвета системной строки на физическом iPhone ещё нужна. Предыдущий коммит 78f1dac: CI 41700815484 прошёл 44/44 этапа, Pages 41700814550 успешен.
