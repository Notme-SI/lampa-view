# Тихая синхронизация — 0.4.97

Основа: a34fbe7 / 0.4.96. Пользователь наблюдает повторные видимые загрузки всей Lampa после публикации.

Подтверждённая причина: progress-sync и watch-history отправляли state:changed favorite/read. Текущий штатный Activity.init обрабатывает read/profile/clear через refresh(true). При открытии активности опять запускался refresh с порогом 5 секунд — получался цикл. Дополнительно collections мог пересоздать главную при отличии старой закладки и новой истории.

Критерии: история CUB загружается один раз до первого показа главной. Дамп TimeCode по-прежнему один раз на профиль, затем дельты. Фоновое событие sync обновляет метки/карточки, не вызывает refresh/replace и не пересоздаёт DOM главной; текущая строка истории сохраняет фокус и читается заново при следующем открытии. Изменённые таймкоды продолжают обмениваться между устройствами. Не отключать синхронизацию ради устранения мигания.

Проверки: unit, браузер с повторяющимися обновлениями и реакцией текущего Activity на favorite/read; сетевое ожидание до начального показа; отсутствие видимого reload при успешном и неуспешном фоне; сборка, обязательные проверки, актуальные CI и Pages.

Результат: полный unit-набор 311/311 перед добавлением отдельного отказоустойчивого сценария; дополнительный сценарий успешен. Chromium/WebKit × десктоп/ТВ: quiet-sync подтверждает один первый показ с порядком CUB, неизменный DOM и отсутствие новых запросов главной после трёх обновлений; следующее явное открытие получает свежий порядок. Timeline-devices подтверждает сохранённый обмен через штатный handler. Home-stage, history-focus и remote-navigation проверяют затронутые маршруты. Физический ТВ не проверялся.
