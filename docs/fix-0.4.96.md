# Общая синхронизация и подписи ТВ — 0.4.96

База: 361ea08 / 0.4.95; исправление дубляжа опубликовано, CI и Pages успешны.

Объём: Windows-приложение и его панель истории НЕ исправлять по прямому указанию пользователя.

Критерии:
- На ТВ размеры «Меньше» и «Нормально»: обычные карточки и история, до двух полных строк названия; год ниже, без наложения. Десктоп и геометрия ТВ-карусели сохраняются.
- Один аккаунт CUB и один профиль дают общий прогресс на настроенном пользователем Lampac. Автоматически обновляются как штатные закладки/ручные отметки CUB, так и реальные записи Timeline.
- TimeCode получает и отдаёт общий профильный Timeline целиком/дельтами без открытия каждой карточки. Нет зависимости от платного клиентского флага для обмена через собственный Lampac.
- Сохранять реальные time/duration/percent и авторское updated; не выводить время из истории, процента или длительности произведения.
- Новая запись/снятие отметки распространяются в обе стороны; старый импорт не перекрывает новую запись, удаления не воскресают. Полученный импорт не создаёт цикл отправки.
- Идентификация по действующему аккаунту и ID профиля CUB; без объединения четырёх областей сервера. При смене аккаунта/профиля старый ответ не применяется.
- Использовать только уже настроенный сервер/авторизацию TimeCode, не зашивать lampac.rest и не публиковать токены. Ограниченные запросы и очередь; скрытый экран и воспроизведение не запускают фоновую массовую работу.
- Сборка, unit, браузерные сценарии подписи всех размеров и двух клиентов; изолированная проверка API Lampac; публикация в существующий main, проверка текущих CI и Pages.

Физический Philips недоступен для автоматической проверки. Два изолированных клиента проверяют обмен данными; это не заменяет проверку реальных устройств.

- Главная использует штатный CUB history/list с group=card: порядок последнего просмотра, без подмены старой закладкой history; постраничная загрузка и изоляция профиля сохраняются.

## Реализация и проверка

Причины: прошлый foreground refresh не обновлял Bookmarks, не опрашивал открытый экран ТВ и не забирал общий TimeCode. Серверный TimeCode использовал другую область для основного профиля и читал лишь текущую карточку. Для общей области теперь явно передаются действующий email аккаунта и ID профиля CUB. Другие области сервера автоматически не объединяются.

Локальный Timeline остаётся штатным: реальные hash/time/duration/percent/updated, события update/read и нативный handler плеера. Новый мост использует существующие dump/changelog/set настроенного TimeCode; очередь до 10000 записей, пачки до 100, два ограниченных сетевых потока, таймауты и backoff. Версия POST не продвигает курсор чтения. Старые импорты и запоздавшие ответы другого профиля не перекрывают новые данные. Полученный прогресс не отправляется повторно.

Главная берёт порядок и страницы из штатного Account.Api.watchHistory(group=card); ручная отметка фильма читается из Favorite.cloud при включённой синхронизации. Ни запуск в Lampa, ни добавление в историю не превращаются в выдуманный таймкод. Обновление видимого экрана каждые 30 секунд, при возвращении и открытии раздела; скрытый экран и плеер приостанавливают фоновые запросы.

ТВ в размерах «Меньше»/«Нормально»: вместо line-clamp используется блочная высота до двух строк с целым пиксельным интервалом, пересчитываемым после изменения масштаба. Короткое название остаётся однострочным, год в обычном потоке ниже. Расчёт ширины плашки измеряет содержимое Range и её фактическое ограничение ширины, а не обрезанный scrollWidth.

Локально: сборка ES5; полный unit-набор с отдельным повтором bridge (первому запуску мешало ограничение записи вне writable roots), затем регрессионные проверки изменённых сценариев; оба Python-набора 7/7 и 3/3. Все 19 обязательных браузерных сценариев прошли. Новые сценарии Chromium/WebKit проверяют строки/историю при 1280/1920 и всех размерах, а также два изолированных профильно авторизованных клиента и штатный Timeline.view(...).handler. Дополнительный home-status актуализирован под отсутствие фиктивного времени и обязательный просмотр всех серий сезона; также прошёл.

Действующий API Lampac проверен в отдельной синтетической области: передача 1304 секунд без изменения, отклонение старого updated, дельта удаления с сохранением duration, изоляция другого профиля. Пользовательские данные и области не изменялись. Это проверка API и двух браузеров, а не физического Philips. После обновления плагина на устройствах требуется пользовательская проверка: длинные названия в двух меньших размерах, реальный просмотр/снятие отметки и получение на другом устройстве примерно за 30 секунд.
