# Пересборка подборок: предложение после разбора SURS

Проверен загрузчик https://aviamovie.github.io/surs.js и его текущие модули v3/surs.js, surs_select.js (2026-11-04). Сам загрузчик не содержит каталога: модули строят discover-запросы TMDB по странам, жанрам, сетям и сортировке, в том числе KR, TR и RU. Это не отдельная база дорам или аниме.

## Предлагаемая структура

- Сериалы: сейчас выходит, новинки, высокий рейтинг; российские, турецкие, британские; криминал, фантастика, комедии. Региональные строки самостоятельны, их можно скрывать и переставлять.
- Дорамы: свежие релизы и текущие; Корея, Китай, Япония, Таиланд; романтика, триллеры/детективы, исторические. Не смешивать с анимацией, документалистикой и реалити.
- ТВ-шоу: российские реалити, ток-шоу, развлекательные; зарубежные — отдельными строками. Конкретные музыкальные/интеллектуальные/путешествия добавлять только при надёжном признаке в базе либо проверенном списке.
- KinoAPI использовать при наличии пользовательского ключа для подтверждённых стран/жанров/годов. В текущем документированном API нет фильтра по сети/стримингу и отдельного признака «шоу о путешествиях»; названия строк не должны обещать такой фильтр.
- Не переносить случайную смену названий/жанров SURS и не подключать его целиком: это меняло бы порядок, настройки и нагрузку.

## Аниме

- Полный абсолютный список провайдера → проверенные арки каталога, одинаковый слой метаданных, без смены координат воспроизведения/Timeline.
- Если провайдер отдаёт меньше серий, не создавать фиктивные сезоны. Число сезонов каталога и доступных у источника различать.
- Именованный сезон отображать двумя строками на баннере: «Сезон N», название арки.
- Общая модель релизов MAL/Shikimori для карточек, франшиз и торрентов всё ещё отдельная незавершённая работа; текущий проход не считать её завершением.

## Конкретный план внедрения (после 0.5.19)

Новая структура в 0.5.19 не включается. Реализовывать отдельными проходами с сохранением скрытых строк, пользовательского порядка и существующих ключей настроек.

1. **Сериалы.** В src/catalogue.js сохранить «Сейчас выходит», новинки и высокий рейтинг; добавить самостоятельные строки стран RU, TR, GB и жанров криминал, фантастика, комедия. Для российских и турецких сериалов использовать with_origin_country, а не язык оригинала. Исключить анимацию, документалистику, реалити и ток-шоу из художественных сериалов. Ввести постоянные ключи строк; изменившиеся URL добавить в minimal_row_aliases, чтобы сохранить скрытие/порядок. Проверка: параметры запросов, «Подробнее» и пагинация, миграция существующих настроек.
2. **Дорамы.** Сохранить отдельные страны KR, CN/TW, JP, TH и общие актуальные/новые релизы; жанровые строки ограничить надёжными TMDB drama/comedy/mystery. «Романтика», «исторические» и «триллеры» требуют проверенных ключевых слов или проверенного списка: у телевизионного discover TMDB нет эквивалентных универсальных жанров. Не переименовывать drama в «романтику» или mystery в «триллер». Для включённого KinoAPI сохранить общий смысл страны/жанра и тот же переход «Подробнее»; отказ API возвращает соответствующую строку TMDB, а не другой жанр.
3. **ТВ-шоу.** Разделить российские реалити и ток-шоу (страна RU, жанры 10764 и 10767) и зарубежные строки. Для зарубежных использовать те же жанры и проверку origin_country в результатах: исключать записи с RU; неизвестную страну не выдавать за зарубежную. Исключение страны не считать доступным discover-фильтром без проверки документации: постфильтрация требует ограниченного добора результатов и согласованной пагинации «Подробнее». Убрать из «Семейных и развлекательных» широкое объединение комедий и семейных сериалов: оно не доказывает формат шоу. Музыкальные, интеллектуальные и путешествия отложить до надёжных списков/признаков; не объявлять фильтры, которых нет в API. Проверить российские и зарубежные результаты на небольших реальных выборках.
4. **Выпуск.** Для каждого прохода: проверки cataloguePlan/фильтров и постфильтрации KinoAPI, отсутствие дубликатов строк, «Подробнее» со второй страницей, сохранение пользовательского порядка/скрытия, сборка и полный обязательный набор CI/Pages. Локальные проверки без скриншотов. Публиковать только после успешных проверок; физические устройства выделять отдельно.

Связанные места: src/catalogue.js, src/kino-catalogue.js, src/rows.js, src/i18n-messages.json; tests/catalogue-feeds.test.cjs, tests/kino-catalogue.test.cjs и tests/rows.test.cjs. SURS целиком не подключать и новый источник данных ему не приписывать.
