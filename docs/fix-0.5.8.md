# 0.5.8 — Исходные эпизоды штатной Lampa

- Подтверждённая причина пропуска второй части: Api.sources.tmdb.get обрезает первый сезон по разрыву даты более 90 дней; исходный список сохраняется в episodes_original.
- При явном сопоставлении частей искать канонические эпизоды в episodes_original, затем episodes. Аналогично строить канонический справочник Online. Не менять данные/нумерацию штатной Lampa и Timeline.
- Проверка проходит через настоящий Api.sources.tmdb.get, а не его подмену: ответ 5/10 эпизодов, русские описания и кадры 1:6–1:10, подпись второй части после переключения.
- Дополнительно проверить сообщения пользователя о Zetflix и переключении сезонов. Не выдавать ожидание провайдера за отсутствие эпизодов. Без скриншотов.

- Быстрые ручные выборы объединяются отложенным обработчиком: 160 мс покоя, не чаще одного обращения за 500 мс. Перед исчерпанием штатного лимита очередь выдерживает 4,1 секунды без запросов: нативный счётчик сбрасывается только после простоя. Сохраняются родные filter.onSelect/request/reset, URL, account()/заголовки и серверные ограничения; транспорт не подменяется.
- reset отменяет предыдущий запрос; поколение ответа защищает parse/getEpisodes/ошибки. Ограничить ожидание запроса 15 секундами, повторить тот же URL штатным request. Уход с экрана отменяет таймеры.
- Пустой/ошибочный ответ отдельного выбранного сезона не помечает весь источник неработающим и не запускает автоматический уход на другой источник.
- Публичная проверка /lite/events для «Люпена»: Zetflix сейчас не выдаётся сервером; Filmix возвращается и его корневой ответ получен за долю секунды. Это не подтверждает доступность каждого сезона или пользовательской сессии Zetflix.

Проверено: сборка ES5; полный набор 369/369 до уточнения очереди; после уточнения — 4/4 сценария навигации, включая минуту непрерывных переключений, и 3/3 регрессии метаданных. Online/озвучки Chromium и WebKit проходят без снимков. Серверные проверки: 7 + 3. Полный финальный набор выполняется также в CI.
